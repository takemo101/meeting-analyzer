# アクター（ACTOR.md）：話者の名前

相手が複数人の会議で、記録・字幕・エージェントのサマリーに、**誰の発言かを名前で出す**ための仕組み。**声からは区別しない**。会話に出てくる人の一覧（`ACTOR.md`）と、**発言の内容**から、名前を付ける。要件は [SPEC §3.13](../SPEC.md)。この文書は使い方（要件の正本ではない）。

## 何が起きるか

| 場所 | 付き方 |
|---|---|
| **本人**（マイク） | ACTOR.md に `本人: はい` の人がいれば、その名前：`本人（山田 太郎）`（推定ではない） |
| **相手**（システム音声） | 発言の内容から、一覧の中の誰かを推定：`相手（推定: 佐藤 花子）`。決められなければ、`相手` のまま |
| 記録（`transcript.md`） | 見出しに、アクターの一覧。行に、上の名前 |
| エージェントへの字幕 | `actor`（名前）・`actorGuessed`（推定か）が付く。`speaker`・`source` は変わらない。開始の出来事に `actorFile`（ACTOR.md のパス） |
| サマリー | エージェントは、まとめる前に ACTOR.md を読み、「相手」でなく、**名前で**書く（推定は「推定」と分かる書き方） |

## ACTOR.md の書き方

```markdown
## 山田 太郎
- 役割: プロダクトマネージャー
- 呼ばれ方: 山田さん, PM
- 話題: 優先順位、スケジュール、リリースの判断
- 本人: はい

## 佐藤 花子
- 役割: バックエンドのエンジニア
- 呼ばれ方: 佐藤さん
- 話題: API、データベース、障害対応
```

- 「## 名前」が 1 人分。UTF-8・64 KB まで・12 人まで。`本人: はい` は、1 人だけ（いなければ、付けない）。
- **話題は、具体的に**書く（推定は、話題と発言の重なりで決まる）。人どうしで話題が重ならないほうが、当たる。
- 名前が呼ばれた人は、**その発言の話者の候補から外れる**（「田中さん、…」と呼ばれた人は、話者ではない）。同じ姓の人が 2 人いるときは、呼ばれ方を区別する（「一郎さん」「二郎さん」）。
- 内容を確かめる：`meeting-analyzer actors check ACTOR.md`（人数・名前・本人・警告）。

エージェントに、「ACTOR.md を作って」と頼むと、プロジェクトの資料（AGENTS.md・README・docs・CODEOWNERS）から、人の情報を取り出して作る（skill `meeting-analyzer-actors`。資料に書いてあることだけ。推測せず、本人に確認する）。入れ方は[プリセットの skill](presets.md) と同じ（`skills/meeting-analyzer-actors/`、またはアプリの `Contents/Resources/skills/meeting-analyzer-actors/` を、エージェントの skill のフォルダへコピーする）。

1. 設定ウィンドウ（メニューの「設定…」）の「**話者（アクター）**」→「選ぶ…」で、ACTOR.md を選ぶ（パスを覚える。**会議の開始のたびに読み直す**ので、編集は次の会議から効く）。読めないときは、アクターなしで会議が始まり、理由がメニューの知らせに出る。
2. 「**相手の話者の推定**」で、判断モデルを選ぶ：**Tiny-Jev 0.6B**（約 1.2 GB。軽く速い）か **Tiny-Jev 1.7B**（約 3.4 GB。精度が高い傾向。メモリも多く使う）。どちらも、Qwen3 を確率つきの判断用に学習した System One 型（Apache-2.0）。「ダウンロード」を押したときだけ、Hugging Face から取得して、SHA-256 で検証する（`meeting-analyzer models download tiny-jev-0.6b`／`tiny-jev-1.7b` でも）。**モデルを選んでいない・取得していないときは、相手の名前は付かない**（「本人」の名前の対応づけだけが働く）。
3. 会議を始める。モデルの読み込みに、数秒かかる（開始処理中。初回は GPU のグラフのコンパイル）。モデルは、この Mac の GPU（Metal）で動き、会議が終わると解放する。

## 推定のしくみ（コードが規則を決め、モデルは確率を返すだけ）

確定した「相手」の発話ごとに：①6 文字未満は付けない。②「佐藤です」のような名乗りは、その人（モデルを使わない）。③名前・呼ばれ方が出た人を、候補から外す。④判断モデルに 2 つ問う：「この発言を話した人は誰か」（候補ごとの確率）と、「この発言は、相づち・同意・あいさつ・進行の言葉だけで、内容を持たないか」（確率）。⑤**最も確からしい人の確率が 0.9 以上で、「内容を持たない」確率が 0.5 未満のときだけ、付ける**。**付けられなければ、「相手」のまま**（当てずっぽうで付けない）。確率のしきい値（0.9・0.5）は、**合成の 30 発言を見て決めた暫定の値**で、実会議で決め直す必要がある。判断モデルの答えは、選択肢の確率だけ（文章を生成しない。発言の中の命令に従う余地がない）。

## 限界（未確認を含む）

- **内容からの推定**で、声からの区別ではない。話題が重なる人・名前の出ない短い発言・複数人が同じ話題を話す会議では、付かない、または、間違う。
- 精度の根拠は、自作の合成の 30 発言の PoC だけ（[検証記録](verification.md)の 2026-10-30）。**実会議の文字起こし・日本語の言い回しの幅・アクターが多いとき（10 人など）は、未確認**。
- 確定した発話ごとに、2 問の待ちが入る：**0.6B は約 140 ms、1.7B は約 300 ms**。読み込みのピークのメモリ：**0.6B は約 2.8 GB、1.7B は約 8.6 GB**（重みのファイルの対応づけを含む。メモリの少ない Mac では、0.6B を選ぶ）。
- 追加できる判断モデルは、**Tiny-Jev 0.6B（約 1.2 GB）と 1.7B（約 3.4 GB。精度が高い傾向）**。2 つは、同じトークナイザのファイルを共有する。日本語の ModernBERT（argos1111/modernbert-ja-310m-jev）・Jev-Style 0.8B は、測定で使えたが、実行の実装が未了（SPEC §11）。

## プライバシー

発言の文字は、この Mac の中で、ダウンロードした判断モデルにだけ渡る（ネットワークへ出ない。ダウンロードのとき、通信するのは、モデルのファイルの取得だけ）。ACTOR.md の内容は、記録の見出し（名前の一覧）と判断モデルへの問いに使うだけで、保存・ログ出力しない。ACTOR.md に、個人情報・秘密は書かない（名前・役割・呼ばれ方・話題だけ）。
