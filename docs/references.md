# 実装の参考資料

実装とレビューで使う設計原則の選択。製品要件の正本は [SPEC.md](../SPEC.md)、構成は [構成説明](architecture.md)、検証は [検証手順と記録](verification.md)。ここに書いた原則は、設計判断の根拠であり、製品要件ではない。

## 出典と扱い

- 設計原則：shortnote の [実装の参考資料](https://github.com/takemo101/shortnote)（[j5ik2o/okite-ai](https://github.com/j5ik2o/okite-ai) の `skills/` を、Swift の言葉に直したもの。MIT）から、必要なものだけを引き継いだ。原則の全文・コード例は転載しない。
- 進め方・文書の構成・検証の方法：shortnote に倣う。製品構成（描画・キーボードショートカットなど）は移さない。
- まとめ方の規則（静けさ 1.2 秒・保持 10 秒・境界・上限 64）は、前身の試作（live-support）の値を受け継いだ。このプロジェクトは、他のプロジェクトに依存しない（単体で完結する）。
- 対象は、小さな単一プロセスのアプリ。**規模に見合わない儀式は持ち込まない。**

## 選んだ原則

| 原則 | 判断 | meeting-analyzer での適用 | レビュー質問 |
|---|---|---|---|
| 変更理由で境界を決める | 採用 | 変わる理由は、規則（まとめ方・状態・記録）、外部の窓口（認識・窓口（ハブ）・MCP）、OS との接点（置き場所・ソケット）、流れの組み立て、見せ方（CLI・メニュー）。それぞれを別のディレクトリにし、依存を下向きだけにする | この変更は、どの理由で変わるのか。その理由を持つ場所は 1 か所か |
| 境界で一度だけ型にする | 採用 | 外から入る値（引数・トークン・送り先・ファイル）は、入口で一度だけ検査して型にする。内側は再検証しない | 検証が、内側で繰り返されていないか。不正な値が、境界を越えて入っていないか |
| 常に有効な値 | 部分採用 | 状態遷移は、不正な遷移を作れない（`SessionLifecycle`）。取り込む音声の選択は、何も選ばれていない状態を `isEmpty` で表す（`AudioSelection`） | 無効な値を、作れてしまっていないか |
| 集合に固有の規則を持つ型 | 部分採用 | 規則がある集合だけを型にする：`Batcher`（まとめ方）、`Transcript`（upsert と並び） | 集合の規則が、あちこちに散っていないか |
| 命じる | 部分採用 | 規則を持つ型に操作を置く（`Batcher.takeBatch`、`SessionPipeline.finish`）。外で読んで `if` で判断し、同じ判断を繰り返さない | 呼び出し側が、内部の状態を読んで判断していないか |
| 目的が同じものだけ共通化する | 採用 | ファイルの再生もライブの取り込みも、同じ `SessionPipeline`。目的が違うもの（`transcribe` の出力と `replay` の送信）は、部品だけ共有する | 似ているだけで、目的が違うものを、無理に共通化していないか |
| 回復できる失敗は型にする | 採用 | 利用者や環境のせいで起こる失敗は、`Result`・`throws` と小さな `enum` にする。見せ方（終了コード・JSON）を決めるのは境界だけ | 失敗が握り潰されていないか。成功に見える代用品になっていないか |
| 純粋な核を先にテストする | 部分採用 | まとめ方・状態遷移・記録・JSON の形を、音声・画面・ネットワーク抜きのテストで先に固め、そのあとで OS との接点を作る | 規則が、OS の操作と混ざっていないか |
| 保存形式の互換 | 部分採用 | エージェントへ渡す JSON の形（`TranscriptEvent`）は、MCP を通してエージェントが読むので、変えるときは `instructions`・skill も直す。記録の Markdown は、エージェントが読む（先頭の注意を保つ） | 形を変えたとき、受け手（`instructions`・skill）も直したか |

## 持ち込まないもの

- **DDD の語彙と部品**（Entity・Aggregate・Bounded Context）、リポジトリ、4 層構成、UseCase クラス。
- **すべてのプリミティブのラップ**。不変条件も取り違えもない値は、素のままにする。
- **全型の protocol 化**。差し替えが実際に要る箇所（出来事の受け口 `EventSink`、発言者ごとの取り込み＋認識 `LiveInputs`、文字起こしの更新）だけ。
- **`Result` / `Either` の外部ライブラリ**。標準の `Result` と `throws` で足りる。
- **数値の目安**（凝集・結合のメトリクス、ディレクトリの深さ、ファイル数）。
- **外部パッケージ**（音声処理・HTTP・JSON・MCP の SDK）。MCP の JSON-RPC は、小さいので、自前で書く。標準フレームワークで足りる間は、足さない。

## 調べた OS の機能（実装・確認の状況）

実装の判断に使った、OS の機能。**確認した範囲だけを、確認済みとして書く**。

| 機能 | 用途 | 確認 |
|---|---|---|
| `SpeechTranscriber`／`SpeechAnalyzer`／`AssetInventory`（Speech） | オンデバイスの文字起こし。言語の対応の確認、モデルの取得、ファイルの解析、確定前の結果 | **確認済み**（macOS 27.0.1・この Mac）：`ja_JP` に対応し、モデルが入っていて、権限の確認なしに、CLI から音声ファイルを解析して結果を得られた。`say` の日本語音声では、専門用語（「Node.js」「LTS」）を誤認した（`doctor`・E2E R1 で再現可能） |
| `AVAudioEngine` のマイク入力とボイス処理（エコー除去） | 自分の声の取り込み。相手の声の回り込みの抑制 | **未確認**（実装前）。効き具合は実機で確認する（SPEC A12） |
| `ScreenCaptureKit`（音声のみのストリーム・画面の撮影） | 会議アプリのシステム音声の取り込み。画面の取り込み | **未確認**（実装前）。ヘッダの存在だけ確認した。権限と、アプリ単位の絞り込みを実機で確認する（SPEC A11・A13） |
| TCC（マイク・画面収録の許可） | 取り込みの権限 | **未確認**。ad-hoc 署名のビルドで、許可がビルドのたびに外れるかを確認する（SPEC §9） |
